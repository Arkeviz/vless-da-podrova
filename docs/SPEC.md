# vless-da-podrova — спецификация

Браузерный «VPN» для личного использования: пускает трафик браузера через собственный
VLESS-сервер (`tcp + reality + xtls-rprx-vision`) по настраиваемым правилам.

- Браузеры: Chromium (Chrome, Edge, Яндекс Браузер) — MV3; Firefox — MV2 (дефолт WXT).
- ОС: только Windows.
- Распространение: для себя, без публикации. Firefox подписывается через AMO как unlisted.
- Не зависит от десктопных клиентов (Throne и т. п.).

## Архитектура

Расширение не умеет говорить по VLESS (нет сырых сокетов). Соединение держит **sing-box**,
который запускает **нативный хелпер** через native messaging.

```
браузер ── PAC / proxy.onRequest ──► 127.0.0.1:<auto>  ─┐
                                    127.0.0.1:<proxy> ─┤ sing-box ── VLESS ──► сервер
расширение ── native messaging ──► helper.exe ── spawn ┘   (Job Object)
```

- **Хелпер** (`packages/helper`): Node/TS, собирается в exe через `bun build --compile`.
  «Тупой»: выделить свободные порты, записать конфиг, запустить/остановить ядро, отдать статус и лог.
  sing-box помещается в Windows Job Object с `KILL_ON_JOB_CLOSE` и умирает вместе с хелпером.
- **Конфиг sing-box** целиком генерирует расширение (`packages/shared`) — единственный источник правды.
- **Входы ядра** (`mixed`, `127.0.0.1`, без авторизации, свободные порты при каждом запуске):
  - `auto` — трафик идёт через правила ядра;
  - `proxy` — всегда VLESS.
- **Clash API** на отдельном свободном порту с секретом на сессию — статус, задержки, трафик.
- `scripts/install.ps1` / `uninstall.ps1`: закреплённая версия sing-box с проверкой SHA256,
  установка в `%LOCALAPPDATA%\vless-da-podrova`, регистрация native host в `HKCU` для
  Chrome, Edge, Яндекс Браузера и Firefox. Имя хоста: `com.vless_da_podrova.helper`.
  ID расширения фиксированы (`key` в манифесте Chromium, `gecko.id` для Firefox).

## Маршрутизация (в порядке приоритета)

1. **Режим «вкладка через прокси»** — весь трафик вкладки в `proxy` (кроме localhost/LAN).
   - Firefox: точно, по `tabId` в `proxy.onRequest`.
   - Chromium: «обучение доменам» через неблокирующий `webRequest` — домены вкладки
     добавляются в PAC. Ограничения: первый запрос к новому домену идёт мимо; выученные домены
     проксируются во всех вкладках, пока режим включён; запросы service worker'ов не привязать.
   - Выученные домены хранятся по сайту, редактируются, можно превратить в постоянные правила.
     Есть список игнорирования (по умолчанию пустой).
   - Режим живёт, пока жива вкладка (переживает переходы), наследуется дочерними вкладками
     (`openerTabId`), есть галочка «всегда для этого сайта». «Выкл.» = обычные правила.
2. **Доменные правила `proxy`/`direct`** — исполняются в браузере (PAC / `onRequest`), мгновенно.
   Кнопка «этот сайт» на три положения (прокси / напрямую / по правилам), по умолчанию —
   регистрируемый домен (`tldts`), точный хост — через меню.
3. **Правила ядра** — `block`, IP/CIDR, rule-set по URL (`.srs`/`.json`, интервал обновления).
   Порядок — drag & drop, первое совпадение.
4. **Действие по умолчанию** — `proxy` или `direct`.

Пресетов нет — всё настраивает пользователь. Типы доменных совпадений: точный, суффикс,
ключевое слово (без регулярок). DNS в ядре — DoH напрямую (по умолчанию `https://1.1.1.1/dns-query`).

## Серверы

- `vless://`-ссылки (ручные серверы, редактируемые).
- Подписки по URL: base64 или plain-список; интервал на подписку (по умолчанию 12 ч), через прокси
  если он включён, ручное обновление. Серверы подписки не редактируются, перезаписываются.
- Ручной выбор сервера + опциональная группа «авто» (urltest).

## Надёжность и приватность

- Ядро живёт, пока включён прокси; состояние восстанавливается при старте браузера.
- Падение ядра: по умолчанию fail-open с уведомлением; kill-switch включается в настройках.
- По умолчанию: защита от WebRTC-утечки (`webRTCIPHandlingPolicy`), удалённый DNS (SOCKS5).

## UI

- Попап и настройки на русском, строки в одном месте (`common/i18n`).
- Иконка: серая — выкл., зелёная — подключено, красная — ошибка. Бейдж текущей вкладки:
  `P` — прокси, `D` — напрямую, `T` — режим вкладки.
- Статус, задержки серверов, трафик, лог ядра (Clash API + хелпер).
- Экспорт/импорт всех настроек в JSON.

## Стек

pnpm-монорепо: `packages/extension` (WXT + TS + Vue 3, структура FEOD), `packages/helper`,
`packages/shared` (типы протокола, парсер `vless://`, генератор конфига), `scripts/`.
Vitest на чистую логику; ручная проверка по чек-листу.

## Этапы

Все пять этапов реализованы; проверка в живом браузере — по чек-листам в README.

1. **Связка**: хелпер, install/uninstall, парсер `vless://`, ручной сервер, генерация конфига,
   вкл/выкл, весь трафик через прокси. Chromium и Firefox.
2. **Правила**: доменные (PAC / `onRequest`), правила ядра, действие по умолчанию, кнопка «этот сайт».
3. **Подписки**, группа «авто», статус и диагностика, иконка с бейджем.
4. **Режим вкладки** (Firefox, затем Chromium с обучением).
5. **Защита от утечек**, kill-switch, бэкап, подпись для Firefox.
