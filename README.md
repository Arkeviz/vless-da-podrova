# vless-da-podrova

Браузерное расширение для Chromium (Chrome, Edge, Яндекс Браузер) и Firefox на Windows, которое пускает
трафик браузера через ваш собственный VLESS-сервер - с гибкими правилами «что через прокси, что напрямую»,
подписками, режимом «эта вкладка через прокси» и защитой от утечек.

Проект для личного использования: в магазины расширений не публикуется и не зависит от десктопных
клиентов вроде Throne, v2rayN или Hiddify.

## Возможности

- **VLESS со всеми популярными транспортами** - `tcp`, `ws`, `grpc`, `httpupgrade`, `h2`;
  security `reality` (с `xtls-rprx-vision`), `tls`, `none`. Сервер добавляется ссылкой `vless://`.
- **Подписки** - base64 или список ссылок, автообновление по интервалу, трафик и срок действия из
  заголовков панели (3x-ui, Marzban и т. п.).
- **Выбор сервера** - вручную или «Авто»: ядро само держит сервер с наименьшей задержкой.
  Смена сервера происходит без перезапуска ядра и без обрыва работы браузера.
- **Правила маршрутизации** - по домену, домену с поддоменами, ключевому слову, IP/CIDR и по rule-set'ам
  sing-box по URL; действия «через прокси», «напрямую», «блокировать»; действие по умолчанию.
- **Кнопка «Этот сайт»** в попапе - прокси / напрямую / по правилам для текущего сайта или сразу
  для всех доменов, которые использует вкладка, в один клик.
- **Режим «вкладка через прокси»** - весь трафик конкретной вкладки, включая CDN и сторонние домены
  (например, twitch.tv вместе с `ttvnw.net` и 7TV), идёт через VLESS, остальные вкладки - по правилам.
- **Домены вкладки** - список всех доменов, к которым обращается страница, с текущим маршрутом
  и быстрым правилом для каждого.
- **Защита от утечек** - WebRTC без прямых соединений, DNS через прокси, kill-switch.
- **Диагностика** - задержка серверов, скорость и трафик, лог ядра, цветная иконка и бейдж на вкладке.
- **Резервная копия** - все настройки в один JSON-файл, в том числе для переноса между Chrome и Firefox.

## Как это устроено

Расширение браузера не может само установить VLESS-соединение: у расширений нет доступа к сырым
TCP/TLS-сокетам. Поэтому соединение держит [sing-box](https://sing-box.sagernet.org/), а запускает его
маленький нативный хелпер, с которым расширение общается через
[native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).

```
браузер ── PAC (Chromium) / proxy.onRequest (Firefox) ──► 127.0.0.1:<auto>  ─┐
                                                         127.0.0.1:<proxy> ─┤  sing-box ── VLESS ──► ваш сервер
расширение ── native messaging ──► vless-da-podrova-helper.exe ── запуск ───┘
```

- **Хелпер** (`vless-da-podrova-helper.exe`) запускается браузером, когда вы включаете прокси, и
  завершается вместе с браузером. Он выделяет свободные порты, запускает sing-box и отдаёт его лог.
  sing-box помещается в Windows Job Object: если хелпер завершится любым способом, ядро гарантированно
  завершится вместе с ним.
- **Конфиг ядра целиком собирает расширение**, хелпер ничего не решает сам.
- У ядра **два локальных входа**: `auto` (трафик идёт через правила ядра) и `proxy` (всегда VLESS).
  Порты случайные при каждом запуске, слушается только `127.0.0.1`.
- Браузер решает, куда отправить запрос: напрямую, во вход `proxy` или во вход `auto`. Правила браузера
  применяются мгновенно, без перезапуска ядра.

### Порядок правил

| Приоритет | Что | Где исполняется |
| --- | --- | --- |
| 1 | Режим «вкладка через прокси» | браузер |
| 2 | Доменные правила «через прокси» / «напрямую» (в том числе кнопка «Этот сайт») | браузер, мгновенно |
| 3 | Правила ядра: «блокировать», IP/CIDR, rule-set'ы - по порядку списка | sing-box |
| 4 | Действие по умолчанию: через прокси или напрямую | sing-box |

Среди доменных правил браузера решает точность: точный хост важнее домена с поддоменами, а тот -
ключевого слова. Локальные адреса (`localhost`, `192.168.*`, `10.*` и т. п.) всегда идут напрямую.

### Режим «вкладка через прокси» в разных браузерах

- **Firefox** - точно: прокси решает по номеру вкладки, другие вкладки того же сайта не затрагиваются.
- **Chromium** - приближённо: PAC-скрипт не знает о вкладках, поэтому расширение смотрит, к каким доменам
  обращается вкладка в режиме, «выучивает» их и отправляет через прокси. Пока режим включён, выученные
  домены идут через прокси во всех вкладках, а первый запрос к ещё не выученному домену может пройти
  мимо прокси - помогает обновление страницы. Выученное хранится по сайту, поэтому со второго раза
  промахов практически нет.

Режим живёт, пока жива вкладка (переживает переходы), наследуется вкладками, открытыми из неё, и может
включаться сам для отмеченных сайтов («Всегда для …»).

## Требования

- Windows 10/11 x64.
- Chrome, Edge или Яндекс Браузер (Manifest V3) и/или Firefox 115+.
- Свой VLESS-сервер или подписка.
- Для сборки: [Node.js 24](https://nodejs.org/) и [pnpm 11](https://pnpm.io/) (`corepack enable`).
  Bun для сборки хелпера ставится как зависимость проекта, отдельно его ставить не нужно.

## Установка

### Из релиза (проще всего)

На странице [Releases](../../releases) скачайте `vless-da-podrova-<версия>.zip`. В нём всё готовое:
расширения для Chromium и Firefox, хелпер, sing-box, скрипты установки и `README.txt` с инструкцией.

1. Распакуйте архив и запустите `install.cmd` - он положит хелпер, sing-box и расширения в
   `%LOCALAPPDATA%\vless-da-podrova` и зарегистрирует хелпер во всех браузерах. Если sing-box в архиве
   не нашёлся, скрипт скачает его с GitHub и сверит SHA256.
2. Перезапустите браузер и загрузите расширение из `%LOCALAPPDATA%\vless-da-podrovaextension`
   (`chrome` - для Chrome / Edge / Яндекса, `firefox` или подписанный `.xpi` - для Firefox) -
   шаги те же, что в [пункте 3](#3-расширение).

### Из исходников

#### 1. Сборка

```bash
pnpm install
pnpm build
```

Получится:

- `packages/extension/.output/chrome-mv3` - расширение для Chromium;
- `packages/extension/.output/firefox-mv2` - расширение для Firefox;
- `packages/helper/dist/vless-da-podrova-helper.exe` - нативный хелпер.

#### 2. Хелпер и sing-box

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

Скрипт:

- копирует хелпер в `%LOCALAPPDATA%\vless-da-podrova`;
- скачивает sing-box закреплённой версии с GitHub и сверяет SHA256 архива с закреплённым в `scripts/sing-box.json`;
- регистрирует хелпер для Chrome, Edge, Яндекс Браузера и Firefox в `HKCU` (права администратора не нужны).

Если хелпер или sing-box запущены (прокси включён), скрипт попросит выключить прокси и повторить.
Можно передать скачанный вручную архив: `-SingBoxZip путь\к\архиву.zip`.

После установки перезапустите браузер.

#### 3. Расширение

- **Chrome / Edge / Яндекс Браузер:** `chrome://extensions` → включить «Режим разработчика» →
  «Загрузить распакованное расширение» → папка `packages/extension/.output/chrome-mv3`.
  ID расширения всегда `ambndojpohhjfclejjpbckmklinejioh` - по нему хелпер узнаёт «своё» расширение.
- **Firefox, постоянно:** подписанный `.xpi` (см. [Подпись для Firefox](#подпись-для-firefox)) -
  открыть файл в Firefox → «Добавить».
- **Firefox, для разработки:** `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» →
  `packages/extension/.output/firefox-mv2/manifest.json`. Такое дополнение живёт до перезапуска Firefox.

В Firefox для приватных окон разрешите расширению работать в них (страница дополнения → «Запускать
в приватных окнах»).

## Использование

### Попап

- **Включить / Выключить** и статус подключения: сервер, версия ядра, скорость и трафик.
  При ошибке - её текст и кнопка «Переподключить».
- **Вкладка через прокси** - переключатель режима для текущей вкладки и «Всегда для этого сайта».
- **Этот сайт** - правило для текущего домена (с поддоменами), только для хоста или сразу для
  **всех доменов вкладки** (например, ozon.ru вместе с ozone.ru и ozonusercontent.com): через прокси,
  напрямую или по правилам. Ниже - как сайт идёт сейчас. «Все домены вкладки» ставят правила на домены,
  которые страница уже загрузила; если нужно, чтобы через прокси шли и домены, которые появятся позже,
  - «Вкладка через прокси».
- **Домены вкладки** - все домены, к которым обращалась страница, сгруппированные по сайтам,
  с маршрутом и быстрым правилом для каждого. В Chromium нужен доступ к сайтам - кнопка «Разрешить».
- **Серверы** - «Авто», ваши серверы и серверы подписок; «Проверить задержку»; поле для ссылок `vless://`.

### Иконка на панели

Цвет - состояние: серый - выключено, жёлтый - подключение, зелёный - подключено, красный - ошибка.
Бейдж - как идёт текущая вкладка: `P` - через прокси, `D` - напрямую, `T` - режим вкладки,
без бейджа - решают правила ядра.

### Настройки

Открываются ссылкой «Настройки» в попапе.

- **Подписки** - добавление по URL, интервал обновления, «Обновить», трафик и срок действия.
- **Правила** - правила браузера и ядра, порядок правил ядра (перетаскиванием или ↑/↓),
  действие по умолчанию.
- **Режим вкладки** - сайты «всегда», выученные домены по сайтам (удалить, «Сделать правилами»,
  «Забыть»), список «Не выучивать».
- **Защита и сеть** - WebRTC, DNS через прокси, kill-switch, уведомления, DoH-сервер ядра.
- **Резервная копия** - сохранить все настройки в файл и загрузить из файла.
- **Диагностика** - состояние, порты, лог ядра с копированием.

## Приватность и безопасность

- **Данные хранятся только локально** в хранилище расширения: серверы (в том числе UUID и ключи),
  подписки, правила, настройки. Файл резервной копии содержит ключи доступа к серверам - храните его как пароль.
- **Расширение обращается только** к хелперу на вашем компьютере, к ядру на `127.0.0.1` и к адресам
  подписок, которые вы добавили. Никакой телеметрии.
- **Защита от утечек** (настройки → «Защита и сеть»):
  - WebRTC не использует прямые соединения в обход прокси, пока прокси подключён;
  - DNS: имена сайтов резолвит ядро (SOCKS5 с именем хоста), провайдер их не видит;
  - DNS самого ядра для «напрямую» и IP-правил идёт через DoH (по умолчанию `https://1.1.1.1/dns-query`);
  - **kill-switch** (выключен по умолчанию): если ядро упало, трафик блокируется до переподключения,
    а не идёт напрямую. Без kill-switch сайты при падении открываются напрямую, и приходит уведомление.
- **Целостность ядра**: sing-box скачивается только закреплённой версии с проверкой SHA256.

### Разрешения

| Разрешение | Зачем |
| --- | --- |
| `proxy` | направлять трафик браузера в ядро |
| `nativeMessaging` | запускать хелпер и общаться с ним |
| `storage` | хранить серверы, правила и настройки |
| `tabs` | видеть адрес вкладок - бейдж на иконке, «Этот сайт», режим вкладки |
| `alarms` | автообновление подписок |
| `privacy` | защита от утечки IP через WebRTC |
| `notifications` | уведомление об обрыве подключения |
| `webRequest` | режим вкладки и «Домены вкладки» (только наблюдение за адресами запросов) |
| `http://127.0.0.1/*` | Clash API ядра: задержки, трафик, смена сервера |
| доступ к сайтам (по запросу) | Chromium: адреса подписок, режим вкладки, домены вкладки |
| `<all_urls>`, `webRequestBlocking` | только Firefox: маршрутизация запросов и kill-switch |

## Решение проблем

| Сообщение или симптом | Что делать |
| --- | --- |
| «Хелпер не установлен или не зарегистрирован» | Запустить `scripts\install.ps1`, перезапустить браузер. Для Chromium проверить, что ID расширения `ambndojpohhjfclejjpbckmklinejioh`. |
| «sing-box не найден рядом с хелпером» | Переустановить `scripts\install.ps1`. |
| «Версия хелпера не совпадает с расширением» | Пересобрать (`pnpm build`) и переустановить хелпер. |
| «Настройками прокси управляет другое расширение» | Отключить другие прокси/VPN-расширения. |
| «Ядро неожиданно завершилось: …» | Текст после двоеточия - причина от sing-box. Полный лог - «Настройки» → «Диагностика». Частая причина - ошибка в ссылке `vless://` (ключ reality, SNI). |
| «Ядро не начало принимать соединения за отведённое время» | Обычно это первое скачивание rule-set'ов: проверить, что их URL доступны через сервер. |
| Подписка: «Не удалось скачать подписку» | Удалить и добавить подписку заново, разрешив доступ к адресу; проверить, что адрес открывается. |
| Сайт открывается не так, как ожидалось | «Домены вкладки» показывают маршрут каждого домена; бейдж на иконке - маршрут страницы. |
| Режим вкладки в Chromium пропускает запросы | Обновить страницу: новые домены выучиваются по ходу работы. |

Свой лог хелпер пишет в `%LOCALAPPDATA%\vless-da-podrova\helper.log`.

## Ограничения

- Только Windows: хелпер и установка завязаны на Windows (Job Object, реестр).
- Транспорт `xhttp` и VLESS-шифрование (`mlkem768x25519plus`) не поддерживаются: их нет в sing-box.
- Chromium показывает предупреждение о расширениях в режиме разработчика - это плата за установку не из магазина.
- Режим вкладки в Chromium приближённый (см. выше).
- Обновления ставятся вручную: пересборка и повторная установка.

## Удаление

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1
```

Скрипт убирает регистрацию хелпера из реестра и удаляет `%LOCALAPPDATA%\vless-da-podrova`
(`-KeepFiles` - оставить файлы). Расширение удаляется в самом браузере.

## Подпись для Firefox

Обычный Firefox ставит навсегда только подписанные расширения. Подпись в канале **unlisted** -
бесплатно и автоматически, в каталоге AMO расширение не появляется.

1. Создайте ключи API на https://addons.mozilla.org/developers/addon/api/key/ (нужен аккаунт AMO).
2. Подпишите:
   ```powershell
   $env:WEB_EXT_API_KEY = "user:…"; $env:WEB_EXT_API_SECRET = "…"; pnpm --filter @vdp/extension sign:firefox
   ```
3. Откройте `packages/extension/.output/signed/*.xpi` в Firefox → «Добавить».

Скрипт сам собирает архив исходников (AMO просит их для собранного кода); инструкция для проверяющих -
[docs/AMO_BUILD.md](docs/AMO_BUILD.md). Каждая новая подпись требует новой версии в
корневом `package.json` (`pnpm version:set`).

## Разработка

```
packages/
  shared/     чистый TypeScript: парсер vless://, подписки, генератор конфига sing-box, PAC,
              правила, протокол хелпера, клиент Clash API, отрисовка иконки (+ тесты)
  helper/     нативный хост: Node/TS → exe через bun, Job Object через bun:ffi (+ smoke-тест)
  extension/  WXT + Vue 3 + TypeScript, структура FEOD (см. packages/extension/README.md)
scripts/      install.ps1 / uninstall.ps1, sing-box.json (версия и хеш ядра), set-version.mjs, package-release.ps1, release/
docs/         SPEC.md - решения и архитектура, TESTING.md - ручная проверка, AMO_BUILD.md
```

| Команда | Что делает |
| --- | --- |
| `pnpm test` | тесты `shared` и расширения (расширение - на фейковом браузере WXT) |
| `pnpm typecheck` | проверка типов во всех пакетах |
| `pnpm build` | сборка расширения для Chromium и Firefox и хелпера |
| `pnpm dev:chrome` / `pnpm dev:firefox` | расширение в режиме разработки с перезагрузкой |
| `pnpm --filter @vdp/helper smoke` | smoke-тест собранного хелпера с поддельным ядром |
| `pnpm version:set 0.3.0` | сменить релизную версию: она хранится только в корневом `package.json`, манифест расширения и хелпер берут её оттуда |
| `pnpm release:pack` | собрать релизный архив `releaseless-da-podrova-<версия>.zip` из уже собранного (`pnpm build`) |
| `pnpm --filter @vdp/extension icons` | перегенерировать PNG-иконки манифеста |
| `pnpm --filter @vdp/extension sign:firefox` | подписать Firefox-сборку через AMO |

- **Ручная проверка** в браузере с настоящим ядром - чек-листы в [docs/TESTING.md](docs/TESTING.md).
- **Обновление sing-box** - сменить `version` и `sha256` архива в `scripts/sing-box.json`: его читают и установка, и сборка релиза.
- **Ключ расширения**: публичный ключ в `wxt.config.ts` фиксирует ID в Chromium; приватный лежит в
  `.keys/` и в git не попадает - он нужен только для упаковки `.crx`.
- Решения по архитектуре и их причины - [docs/SPEC.md](docs/SPEC.md).

### Выпуск релиза

Релизы собирает GitHub Actions ([release.yml](.github/workflows/release.yml)) по тегу `v<версия>`:

```bash
pnpm version:set 0.3.0
git commit -am "Версия 0.3.0"
git tag v0.3.0
git push --follow-tags
```

Workflow проверяет, что тег совпадает с версией в корневом `package.json`, прогоняет типы и тесты,
собирает расширения и хелпер, упаковывает архив (`scripts/package-release.ps1`) и создаёт GitHub Release
с этим архивом. Локально то же самое: `pnpm build` и `pnpm release:pack` (нужен PowerShell 7, `pwsh`).

Чтобы в архив попал подписанный `.xpi` для Firefox, добавьте в репозиторий секреты `WEB_EXT_API_KEY` и
`WEB_EXT_API_SECRET` (ключи AMO, см. [Подпись для Firefox](#подпись-для-firefox)). Без них релиз
выходит с распакованным Firefox-расширением, которое ставится только временно.
