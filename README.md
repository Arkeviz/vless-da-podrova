# vless-da-podrova

Браузерное расширение, которое пускает трафик браузера через собственный VLESS-сервер.
VLESS-соединение держит sing-box, его запускает нативный хелпер через native messaging.
Решения и этапы описаны в [docs/SPEC.md](docs/SPEC.md).

```
packages/
  shared/     парсер vless://, генератор конфига sing-box, PAC, протокол хелпера (+ тесты)
  helper/     нативный хост (Node/TS → exe через bun), Job Object для sing-box
  extension/  WXT + Vue 3, структура FEOD
scripts/      install.ps1 / uninstall.ps1
```

## Сборка

```bash
pnpm install
pnpm test        # shared + расширение (фейковый браузер WXT)
pnpm build
```

`pnpm build` собирает расширение в `packages/extension/.output/chrome-mv3` и `.output/firefox-mv2`
и хелпер в `packages/helper/dist/vless-da-podrova-helper.exe`.

## Установка хелпера

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1
```

Скрипт копирует хелпер и sing-box в `%LOCALAPPDATA%\vless-da-podrova` и регистрирует
native host в `HKCU` для Chrome, Edge, Яндекс Браузера и Firefox. Версия sing-box закреплена в
скрипте вместе с SHA256 архива. Пока хеш не вписан, скрипт печатает хеш скачанного архива и
останавливается: сверьте его и впишите в `$SingBoxSha256` (или запустите с `-AllowUnpinnedHash`).

Удаление: `scripts\uninstall.ps1`.

## Загрузка расширения

- **Chrome / Edge / Яндекс:** `chrome://extensions` → режим разработчика → «Загрузить распакованное» →
  `packages/extension/.output/chrome-mv3`. ID должен быть `ambndojpohhjfclejjpbckmklinejioh`
  (его фиксирует `key` в `wxt.config.ts`; приватный ключ лежит в `.keys/`, в git не попадает).
- **Firefox:** для разработки — `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» →
  `packages/extension/.output/firefox-mv2/manifest.json` (живёт до перезапуска). Постоянно — подписанный
  `.xpi` (ниже). Для приватных окон разрешите расширению работать в них.

## Подпись для Firefox

Обычный Firefox ставит навсегда только подписанные расширения. Подпись в канале **unlisted** —
бесплатно и автоматически, в каталоге AMO расширение не появляется.

1. Создайте ключи API на https://addons.mozilla.org/developers/addon/api/key/ (нужен аккаунт AMO).
2. Подпишите:
   ```powershell
   $env:WEB_EXT_API_KEY = "user:…"; $env:WEB_EXT_API_SECRET = "…"; pnpm --filter @vdp/extension sign:firefox
   ```
3. Откройте `packages/extension/.output/signed/*.xpi` в Firefox → «Добавить».

Скрипт сам собирает архив исходников (AMO просит их для собранного кода), инструкция для проверяющих —
[docs/AMO_BUILD.md](docs/AMO_BUILD.md). Перед каждой новой подписью поднимите `version` в
`packages/extension/package.json`.

## Ручная проверка (этап 1)

1. Хелпер не установлен → «Включить» показывает ошибку про `install.ps1`.
2. После `install.ps1` и перезапуска браузера: добавить ссылку `vless://…` → сервер появился и выбран.
3. «Включить» → статус «Подключено», версия ядра видна; https://ifconfig.me показывает IP сервера.
4. `http://localhost`, адреса `192.168.*` открываются напрямую.
5. «Выключить» → IP снова свой, процесс `sing-box.exe` исчез из диспетчера задач.
6. Включить и закрыть браузер → `sing-box.exe` и хелпер завершились.
7. Включить, перезапустить браузер → подключение восстановилось само.
8. Включить, убить `sing-box.exe` в диспетчере задач → статус «Ошибка», сайты открываются напрямую;
   «Переподключить» поднимает ядро снова.
9. Переключить сервер при включённом прокси → ядро перезапускается с новым сервером.
10. Повторить 3–6 в Firefox.

## Ручная проверка (этап 2: правила)

Правила редактируются на странице «Настройки» (ссылка в попапе).

1. На youtube.com в попапе «Этот сайт» → «Через прокси» при действии по умолчанию «Напрямую»:
   youtube идёт через прокси сразу, без перезапуска ядра (время «Подключено» не сбрасывается).
2. «только music.youtube.com» → «Напрямую»: точное правило важнее правила для домена.
3. «По правилам» снимает правило.
4. Правило ядра «IP / CIDR» `149.154.160.0/20` → «Через прокси» перезапускает ядро; Telegram Web
   ходит через прокси при действии по умолчанию «Напрямую».
5. Rule-set по URL (`.srs`) скачивается через VLESS; в логе ядра нет ошибок загрузки.
6. «Блокировать» для домена: сайт не открывается, остальные — открываются.
7. Порядок правил ядра меняется перетаскиванием и кнопками ↑/↓; срабатывает первое совпадение.
8. Повторить 1–3 в Firefox.

## Ручная проверка (этап 3: подписки, «авто», диагностика)

1. Настройки → «Подписки» → добавить URL подписки. Chromium спросит доступ к адресу — разрешить.
   Подписка скачалась: число серверов, трафик и срок (если панель отдаёт `subscription-userinfo`).
2. Серверы подписки появились в попапе отдельной группой; удалить их можно только вместе с подпиской.
3. Переключение сервера при включённом прокси не перезапускает ядро (время «Подключено» не сбрасывается),
   а https://ifconfig.me показывает IP нового сервера.
4. «Авто — наименьшая задержка»: ядро перезапускается, под статусом видно «авто → <сервер>».
5. «Проверить задержку» показывает мс для каждого сервера; недоступный — «нет ответа».
6. Под статусом видна скорость ↑/↓ и суммарный трафик.
7. Иконка: серая — выключено, жёлтая — подключение, зелёная — подключено, красная — ошибка.
   Бейдж `P`/`D` на вкладке соответствует правилам; без правил ядра — действию по умолчанию.
8. Настройки → «Диагностика»: состояние, версия ядра, порты, лог ядра (обновить, копировать).
9. Автообновление: интервал подписки 1 ч, через час «обновлена …» сдвинулось само.

## Ручная проверка (этап 4: режим вкладки)

Действие по умолчанию — «Напрямую», для twitch.tv правил нет.

1. **Firefox:** на twitch.tv включить «Вкладка через прокси» — бейдж `T`, стрим грузится через прокси
   (в «Диагностике» → лог ядра видны соединения к `*.ttvnw.net`, `7tv.app`). Во второй вкладке twitch.tv
   без режима идёт напрямую.
2. **Chromium:** включить режим — браузер спросит доступ к сайтам, разрешить. Обновить страницу:
   в настройках → «Режим вкладки» появились выученные домены twitch.tv. Повторное включение на
   twitch.tv работает без промахов с первой загрузки.
3. Ссылка из вкладки в режиме, открытая в новой вкладке (или поп-аут чата), — тоже в режиме.
4. Переход внутри вкладки на другой сайт режим не выключает; закрытие вкладки — выключает.
5. «Всегда для twitch.tv»: новая вкладка с twitch.tv сама включает режим.
6. Правило «напрямую» для twitch.tv не мешает режиму вкладки (режим важнее).
7. «Не выучивать»: добавить `google.com` — запросы к Google из вкладки в режиме не выучиваются.
8. «Сделать правилами» переносит сайт и выученные домены в правила браузера «через прокси».

## Ручная проверка (этап 5: защита, kill-switch, бэкап)

Настройки → «Защита и сеть»:

1. WebRTC: при включённом прокси https://browserleaks.com/webrtc не показывает реальный IP;
   после выключения прокси WebRTC снова работает как обычно.
2. DNS через прокси: https://dnsleaktest.com показывает DNS сервера, а не провайдера.
3. Kill-switch включён, прокси подключён → убить `sing-box.exe`: сайты не открываются,
   в попапе «Kill-switch: трафик заблокирован», локальная сеть доступна. «Переподключить» — снова работает.
   «Выключить» снимает блокировку.
4. Kill-switch выключен → то же падение: сайты открываются напрямую.
5. Уведомление об обрыве приходит при падении ядра и не приходит при ручном выключении.
6. DoH: сменить на `https://dns.google/dns-query` — ядро перезапускается, в «Диагностике» → лог без ошибок.
7. Бэкап: «Сохранить в файл» в Chrome → «Загрузить из файла» в Firefox — серверы, подписки, правила,
   настройки на месте.

Smoke-тест хелпера с поддельным ядром: `pnpm --filter @vdp/helper smoke`.
